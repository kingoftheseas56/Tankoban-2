PART A — Shared QNetworkAccessManager observer (4 commands lit)

Reference: 15+ files currently create their own QNetworkAccessManager (grep for `new QNetworkAccessManager` to enumerate). v1.9's network-* commands returned `unsupported` because no shared observer existed.

Add minimal centralized observer at `src/core/network/NetworkAccessObserver.{h,cpp}` (NEW). Singleton with a static `instance()` accessor + a `registerManager(QNetworkAccessManager*)` hook. Observer connects to each registered manager's `finished` signal + maintains a rolling ring buffer of the last N=100 completed requests (capture: URL, HTTP method, status code, duration ms, response size, finish timestamp). Also tracks currently-pending requests via `QNetworkReply::finished` signal — emits add/remove events on the observer's internal list. Thread-safe via QMutex.

Wire all existing 15+ QNetworkAccessManager creation sites to call `NetworkAccessObserver::instance().registerManager(this)` right after construction. Grep entry-points: `src/core/manga/*`, `src/core/book/*`, `src/core/stream/*`, `src/ui/pages/TankorentPage.cpp`, `src/ui/pages/TankoLibraryPage.cpp`. Surgical wire — one line per site, no refactor of the call shape.

Lit commands:
1. `network-list-requests [--limit N]` — last N completed requests from ring buffer
2. `network-get-active` — currently-pending requests list
3. `network-throttle-set <bandwidth-bytes-per-sec>` — bandwidth throttle (write-gated `TANKOBAN_DEV_WRITE=1`) — implemented via `QNetworkRequest::Attribute::BackgroundRequestAttribute` + a global throttle field on the observer that hooks into pre-send
4. `network-block-host <host>` — addon outage simulation (write-gated `TANKOBAN_DEV_WRITE=1`) — observer maintains a blocked-host set; intercepts in pre-send via signal connection; returns synthetic `QNetworkReply::ServiceUnavailableError` when matched

────────────────────────────────────────────────────────────────────────────────
PART B — Perf counters (3 commands lit)

Reference: v1.9's perf-* counter commands returned `unsupported` because no counter infra exists. Tankoban has `m_stats*` fields in `SidecarProcess.cpp` + IPC latency in `out/ipc_latency.log` but no UI-thread frame-time / CPU / GPU counter.

Add `src/devtools/PerfCounters.{h,cpp}` (NEW). Three counter classes:

1. **FrameTimeCounter** — hooks into `MainWindow`'s paint cycle via `QObject::eventFilter` on the central widget; captures wall-clock between consecutive `QEvent::Paint` events; ring buffer of last N=120 frame durations (≈2 seconds at 60 FPS). Lit: `perf-get-frame-times`.

2. **CpuUsageCounter** — Windows-only — uses `GetProcessTimes` Win32 API on a 250ms QTimer to sample kernel + user CPU time; computes rolling % over last 1s window. Returns `unsupported` on non-Windows (graceful). Lit: `perf-get-cpu-usage`.

3. **GpuUsageCounter** — Windows-only — uses NVAPI / DXGI / Performance Counter API to sample GPU utilization. If neither available at build time, return `unsupported` with reason "no GPU counter API available." Lit: `perf-get-gpu-usage`.

All three counters initialize lazily on first query (no startup cost for non-dev runs). Storage is in-memory only.

────────────────────────────────────────────────────────────────────────────────
PART C — VideosScanner pause/resume API (3 commands lit)

Reference: `src/core/scanner/VideosScanner.{h,cpp}` is currently a one-shot worker — starts in its own QThread, walks the filesystem, emits `scanFinished`, exits. No pause/resume/abort API.

Add to `VideosScanner`:
- `std::atomic<bool> m_paused{false}` + `std::atomic<bool> m_aborted{false}` private fields
- Public slots: `pause()` / `resume()` / `abort()`
- Inside the recursive walk function: check `m_paused` in a tight loop with `QThread::msleep(50)` polling; check `m_aborted` and bail out early with `scanAborted` signal emit if true
- New signal `scanStateChanged(bool paused, bool aborted)` for observers

Lit commands:
1. `scanner-pause [<mode>]` — pause scanner for given mode (write-gated `TANKOBAN_DEV_WRITE=1`); if no mode arg, pause all active scanners
2. `scanner-resume [<mode>]` — resume scanner for given mode (write-gated)
3. `scanner-trigger <path>` — trigger a fresh scan starting at the given root path (write-gated)

`scanner-get-status` (already lit in v1.9) extends to surface the new `paused` / `aborted` state from the atomic fields.

PART D — PosterCache stats accessor (1 command lit)

Reference: `src/core/manga/PosterCache.{h,cpp}` has a private `QHash<QString, QPixmap> m_cache` but no public size accessor and no hit-counter tracking.

Add to `PosterCache`:
- Public `int size() const` returning `m_cache.size()`
- Public `qint64 totalBytes() const` summing pixmap byte sizes across the hash
- Private `std::atomic<qint64> m_hits{0}` + `std::atomic<qint64> m_misses{0}` counters; increment on every `get()` call (existing accessor)
- Public `qint64 hits() const` + `qint64 misses() const` + `double hitRate() const` (returns -1.0 if hits+misses == 0 — sentinel for "no data yet")

Lit: `cache-get-stats` returns aggregate across all cache layers. PosterCache is the first layer with real stats; other layers (EdgeTTS LRU, VideosScanner duration cache, AniList disk cache, etc) ship without hit-rate fields until their owning agents add the same pattern.

────────────────────────────────────────────────────────────────────────────────
PART E — Signal-tracer infrastructure (1 command lit)

Reference: v1.9's `app-trace-signals <objectName>` returned `unsupported` — no signal-tracer existed.

Add `src/devtools/SignalTracer.{h,cpp}` (NEW). Per-objectName subscription manager. When `start(objectName)` is called, looks up the target via `findChild<QObject*>(objectName)`, then uses `QMetaObject::connect` (signal index resolution at runtime) to connect a generic logger lambda to every signal exposed by the object's metaObject. Captured emissions go to an in-memory ring buffer (last N=500 events per traced object) — capture: signal name, arg count, arg type names, emission timestamp. `stop(objectName)` disconnects all traced signals. `get(objectName)` returns the ring buffer.

Lit: `app-trace-signals <objectName> <start|stop|get>` — three-mode operation. `start` returns `{ok:true, signal_count:N}`; `stop` returns `{ok:true, captured_count:K}`; `get` returns the events array.

Write-gate: `TANKOBAN_DEV_WRITE=1` required for `start` and `stop` (they mutate runtime signal-graph); `get` is read-only.
