## Strategic intent

Pywinauto-mcp pixel-clicks fail intermittently on Qt custom widgets — Agent 1's checkbox-rendering-as-`[` saga on 2026-05-18 took 4 round-trips because UIA couldn't reliably target the QLabel-inside-QToolButton. The cleanest fix is bypassing UIA entirely: synthesize the click / keypress / text-input in-process via `QMetaObject::invokeMethod` against the target widget's slot, or via `QApplication::postEvent` for synthetic input events. 100% reliable, no pixel coords, no UIA flakiness.

This commission introduces a new `UiInteractionDispatcher` class that handles QObject lookup by `objectName` + synthetic event dispatch. It's the highest-leverage cross-cutting addition because it unblocks every domain's UI smoke discipline — table-row clicks, button invokes, keyboard nav, text input — without pywinauto-mcp dependency.

## Command catalog (13 commands)

Baseline (8 commands per main spec §Detailed catalog Track B v1.7):
- `ui-click <objectName>` — fires `QAbstractButton::animateClick()` or generic `QMetaObject::invokeMethod("click")`
- `ui-keypress <objectName> <key>` — fires QKeyEvent (Qt::Key code) on target
- `ui-text-input <objectName> <text>` — fires `setText()` + `textChanged` signal
- `ui-query-widget <objectName>` — returns `{visible, enabled, geometry, text, className}`
- `ui-query-focus` — returns the objectName of the currently focused widget
- `ui-active-layer` — returns current view stack (e.g. `comics/library → series-view`)
- `ui-simulate-scroll <objectName> <delta>` — fires QWheelEvent
- `ui-simulate-mouse <objectName> <event-type> [x] [y]` — fires QMouseEvent (press/release/move)

Additional from Codex audit gap-fill (5 commands):
- `ui-list-widgets [filter]` — discover objectName, className, visibility, enabled state, and geometry BEFORE acting
- `ui-wait-for <objectName|condition> <timeout-ms>` — wait for async UI state without polling pywinauto
- `ui-set-checkbox <objectName> <true|false>` / `ui-set-combo <objectName> <value>` — drive common widgets semantically
- `ui-select-table-row <objectName> <row>` — cover the table/list row path that caused recent source-row click drift
- `ui-dry-run <command...>` — resolve target and report planned event without firing it

## Constraints

- **Additive only.** Schema versioning per `DevControlServer.h:24`.
- **Hard-gate behind TWO flags:** `--dev-control` (existing) AND a new `TANKOBAN_DEV_UI_SIM=1` env var. Per Codex anti-pattern #2 in main spec, synthetic UI is powerful and must be unreachable in production. If `TANKOBAN_DEV_UI_SIM` is unset, all `ui-*` commands return `UI_SIM_DISABLED` error.
- **Read-only commands** (`ui-query-widget`, `ui-query-focus`, `ui-active-layer`, `ui-list-widgets`, `ui-dry-run`) do NOT require the second flag — only the `--dev-control` flag.
- **`ui-list-widgets` filter syntax:** support kebab-case object-name globs (`*Table*`, `Stream*`). Default limit 100 results to prevent giant dumps.
- **`ui-wait-for` condition syntax:** support `<objectName>:visible`, `<objectName>:enabled`, `<objectName>:text-matches:<regex>`. Timeout default 5000ms; cap at 30000ms.
- **`ui-select-table-row` test:** smoke against Comics sources panel OR TankoLibrary results (table-heavy domains per Codex Cross-track dependencies item #6) — these are the failure modes that motivated v1.7.
- **ASCII-only emissions** per Rule 16.
- **Build_check.bat = BUILD OK** before commit.
- **Anti-pattern #10 in main spec:** synthetic UI proves a widget received an event. It does NOT prove the screen looks right. Visual smokes still need screenshots or Hemanth's eyes. Don't replace visual verification with synthetic-event success.
