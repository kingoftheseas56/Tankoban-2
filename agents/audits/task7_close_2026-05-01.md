## Deliverables (5 fixes)

### (1) MpvVideoWidget gets `setMouseTracking(true)`
- **Was:** QOpenGLWidget default = mouseMoveEvent only fires when a mouse button is pressed; hover-only mouse moves over the canvas never fired the event → bottom HUD never revealed on hover via VideoPlayer's mouseMoveEvent handler.
- **Now:** mirror FrameCanvas.cpp:38 — setMouseTracking(true) in MpvVideoWidget constructor. Hover bubbles up to VideoPlayer via Qt's default event propagation.
- **File:** src/ui/player/MpvVideoWidget.cpp:39-49 (~10 LOC including comment block).

### (2) Pattern C — seek-accumulation bug fix (m_pendingSeekTargetSec accumulator)
- **Was:** `seekBy` lambda read `m_seekBar->value()` for the base. m_seekBar value lags backend position by ~200ms because it echoes time_update events. Rapid double-tap of arrow keys read the same stale base twice → both presses computed identical target → visible center-flash on second press but position didn't advance. Backend-independent UI bug — identical on both ffmpeg and mpv paths.
- **Now:** added `m_pendingSeekTargetSec` member to VideoPlayer.h. seekBy uses it as base if non-sentinel (≥0); clears in onTimeUpdate when position lands within ±1s of target. Each press accumulates target onto the pending value, not the lagging seekbar.
- **MCP-verified empirically:** paused at 999.29s, sent 2 right-arrow keystrokes ~50ms apart → position 1019.23s (Δ +19.94s). Pre-fix would have been Δ +10s.
- **Files:** src/ui/player/VideoPlayer.h:715-726 (~10 LOC declaration + comment); src/ui/player/VideoPlayer.cpp:1064-1075 onTimeUpdate clear (~10 LOC); src/ui/player/VideoPlayer.cpp:3146-3168 seekBy accumulator (~25 LOC including comment block).

### (3) Cursor auto-hide on mpv path
- **Was:** showControls/hideControls only called `m_canvas->unsetCursor()` / `m_canvas->setCursor(Qt::BlankCursor)`. On mpv path, m_mpvWidget is the active video widget; cursor blank/unblank never reached it → cursor stayed visible regardless of HUD state.
- **Now:** mirror the m_canvas calls — hideControls also calls `m_mpvWidget->setCursor(Qt::BlankCursor)`; showControls also calls `m_mpvWidget->unsetCursor()`. Cursor blanks symmetrically on both backends when HUD hides.
- **Hemanth-verified:** "the cursor auto hide issue has been resolved."
- **File:** src/ui/player/VideoPlayer.cpp:2698 + 2747 (~4 LOC including comments).

### (4) Seekbar focus thief NoFocus
- **Was:** m_seekBar (QSlider subclass) had default Qt::StrongFocus. Click on the slider transferred keyboard focus from VideoPlayer to slider. Subsequent keypresses (space, arrows, F, Esc) routed to QSlider's default handlers (which only handle slider arrow-step) instead of VideoPlayer::keyPressEvent. All other interactive children (buttons, chips) already had Qt::NoFocus.
- **Now:** `m_seekBar->setFocusPolicy(Qt::NoFocus);` matches the existing pattern. Mouse-drag scrub still works; keyboard focus stays on VideoPlayer.
- **File:** src/ui/player/VideoPlayer.cpp:1486 (~10 LOC including comment).

### (5) Esc shortcut scope fix on 3 pages (the actual root cause for Esc not working)
- **Was:** VideosPage, ComicsPage, BooksPage each registered `QShortcut(Qt::Key_Escape, this)` with **default `Qt::WindowShortcut` context** — meaning each page's Esc shortcut fired on ANY Esc press in MainWindow regardless of which page was visible. When VideoPlayer was shown atop the QStackedWidget, VideosPage was hidden but its Esc shortcut still ate Esc at the window level — never reached VideoPlayer's keyPressEvent.
- **Diagnosis steps:** sent F via MCP → `[VideoPlayer] keyPress key=0x46 mods=0x0 action='toggle_fullscreen'` log appeared. Sent Esc via MCP → no log. Confirmed Esc was being intercepted upstream of VideoPlayer. Grepped Qt::Key_Escape, found 3 QShortcuts on VideosPage:820, ComicsPage:133, BooksPage:548.
- **Now:** all 3 pages call `escShortcut->setContext(Qt::WidgetWithChildrenShortcut)` so the shortcut only fires when that page (or its descendants) has focus. When player is shown, page is hidden in stack → no focus → Esc reaches VideoPlayer.
- **MCP-verified after the fix:** Esc on Vinland → log line `[VideoPlayer] keyPress key=0x1000000 mods=0x0 action='back_to_library'` → player closes → `videoPlayerVisible: false` + `activePageId: "comics"`.
- **Files:** src/ui/pages/VideosPage.cpp:820-829 (~12 LOC); src/ui/pages/ComicsPage.cpp:133-141 (~10 LOC); src/ui/pages/BooksPage.cpp:548-556 (~10 LOC).
