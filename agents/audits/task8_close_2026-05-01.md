## Deliverables

### (1) sendSetAudioSpeed → no-op on mpv ✅
- **Was:** routed to `sendSetRate(speed)` which writes the `speed` mpv property — this changes PLAYBACK speed (video + audio together). Actively harmful for the audio-sync use case.
- **Now:** function accepts the IPlayerBackend call but does nothing. Comment explains: mpv handles A/V sync internally via its own audio clock + resampler (audio-pts mode). The ffmpeg sidecar's manual ±5% drift correction is for ITS OWN custom clock; mpv doesn't need it.
- **File:** src/ui/player/MpvBackend.cpp:926-936 (~10 LOC including comment).

### (2) sendSetDrcEnabled → af-add / af-remove with `@drc:` label ✅
- **Was:** `setOpt("af", "acompressor"|"")` — OVERWROTE the entire audio filter chain on every toggle. Other filters (sendRawFilters, future EQ via Task 9) would get clobbered.
- **Now:** uses mpv's `af-add` / `af-remove` commands with a `@drc:` label. enabled → `cmdAsync({"af-add", "@drc:acompressor"})`; disabled → `cmdAsync({"af-remove", "@drc"})`. The label-prefix lets us add/remove this specific filter by name without touching neighbors.
- **File:** src/ui/player/MpvBackend.cpp:938-957 (~20 LOC including comment).

### (3) Per-device audio-delay recall — DEFERRED to Task 8.B ⏸
- **Why deferred:** the proper fix needs a Windows audio device-change watcher (`IMMNotificationClient` COM subscriber), not a 1-file MpvBackend.cpp tweak. mpv's `audio-device` property returns `"auto"` until user explicitly sets it via UI; system audio device changes don't auto-update it. Without device-change detection, the recall key on mpv collapses to `"auto/wasapi"` — same key for speakers AND Bluetooth headphones, defeating per-device behavior.
- **Hemanth ratification:** "go with your recommendation" (after I laid out option A "ship #1+#2, defer #3" vs option B "do all 3 now with WASAPI watcher (~3-4 builds)").
- **Task 8.B scope (~100 LOC + 1 build, queued):** new `src/ui/player/AudioDeviceWatcher.{h,cpp}` Windows COM subscriber implementing `IMMNotificationClient::OnDefaultDeviceChanged`. On change → emit signal → VideoPlayer re-emits `mediaInfo` with new device name → existing recall logic at VideoPlayer.cpp:3753+ applies the saved offset for that device.
